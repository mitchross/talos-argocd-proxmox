# Immich — self-hosted photos

**Purpose:** describe the repository-owned Immich application and its storage. **Status:** current Git configuration; production health must be verified after rollout.

Immich serves the photo catalog through the internal `photos.vanillax.me` route. Its server and CPU machine-learning workload share a node through pod affinity. The server uses a plain PostgreSQL Deployment and ephemeral Valkey. Original photos are mounted read-only from TrueNAS through NFS CSI.

| Data | Owning resource | Recovery |
|---|---|---|
| Original photos | Static NFS CSI volume, `/mnt/photos` | NAS data protection; Immich cannot modify the originals |
| Thumbnails, previews and generated media | `library`, 50 GiB Longhorn PVC | kopiur backup and restore-before-bind |
| Machine-learning model cache | `immich-ml-cache`, 20 GiB Longhorn PVC | Regenerable cache |
| Catalog, albums, metadata and embeddings | `immich-postgres-data`, 20 GiB Longhorn PVC | Hourly kopiur snapshot with a PostgreSQL CHECKPOINT hook |
| Valkey cache | Ephemeral volume | Regenerated by the application |

The database Service is `immich-postgres.immich.svc.cluster.local:5432`. Database credentials come from the `immich-db-credentials` ExternalSecret and are shared by the server and PostgreSQL. PostgreSQL remains major version 17, with VectorChord 0.4.3 and pgvector 0.8.1. Read the [database patch and acceptance runbook](postgres/UPGRADE.md) before changing the image or extensions.

Argo CD discovers this directory through the My-Apps ApplicationSet. [kustomization.yaml](kustomization.yaml) declares the application, scripts, monitoring and backup resources. The server and database use `Recreate` because their data PVCs are RWO. Database monitoring has a dedicated metrics Service and ServiceMonitor; its exporter does not own database readiness.

## External library

The static NFS volume points to `192.168.10.133:/mnt/BigTank/photos/All`, mounted at `/mnt/photos` in both server and machine-learning Pods. Add that path through Immich's external-library administration screen. Use periodic scans: remote NFS changes do not provide reliable local filesystem notifications.

Moving original files on the NAS can break their associations with catalog records. Immich UI edits do not overwrite the read-only originals. Keep the NAS data and database recovery plans together: surviving source files alone do not preserve albums, face tags and catalog metadata.

## Recovery

The database and library use kopiur with restore-before-bind; there is no CNPG operator, Barman archive or VolSync path. A rebuilt PVC waits for kopiur restoration before binding. An already Bound PVC is not restored automatically during an ordinary Deployment update.

Use the canonical [disaster-recovery runbook](../../../docs/disaster-recovery.md) and [kopiur architecture guide](../../../docs/domains/storage/kopiur-backup-architecture.md). After recovery, verify timeline browsing, thumbnails, semantic search, face search and the next successful backup. Do not delete the namespace as a recovery shortcut: it owns the application data PVCs.
